    Subsection Dijkstra’s Algorithm

    Definition 157. Algorithm.

    What makes a procedure an algorithm?
    🔗
    🔗
    🔗
    🔗
    Guess-and-check becomes difficult when a graph has many possible routes. Dijkstra’s algorithm keeps track of the best distances found so far. Following the textbook, we begin at the destination and work backward. Here, distance means the sum of the weights, even when the weights measure time or cost.
    🔗

    Algorithm 158. Dijkstra’s Algorithm: Complete the Key Ideas.

    Use this procedure when all edge weights are nonnegative. The graphs in these notes are undirected.
    🔗
    1. Give the vertex a distance of \(0\) and designate it as current. Give every other vertex a tentative distance of \(\infty\text{,}\) meaning that no route has yet been found.
      🔗
      🔗
    2. For each unvisited vertex adjacent to the current vertex, add the connecting edge’s weight to the current vertex’s distance. Replace the vertex’s recorded distance only if the new distance is . When replacing a distance, also record the current vertex as the next vertex on the route toward the destination.
      🔗
      🔗
    3. Mark the current vertex as . Its distance is now final; do not change its label or use it as an unvisited vertex again.
      🔗
      🔗
    4. Choose the unvisited vertex with the finite recorded distance as the new current vertex. Repeat Steps 2–4 until the starting vertex has been visited.
      🔗
      🔗
    🔗
    If two unvisited vertices have the same smallest distance, either may be chosen. If a new route has the same distance as an existing label, keep the existing label. If no unvisited vertex has a finite distance and the starting vertex is still unvisited, there is no route from the start to the destination.
    🔗
    🔗

    Remark 159. Recording and Recovering the Route.

    A label such as \(9(C)\) means that the best route found so far has total weight \(9\) and goes next to vertex \(C\) toward the destination. Once the starting vertex has been visited, follow the recorded next vertices until you reach the destination. List the entire route and add its edge weights to check the total.
    🔗
    To find distances to the same destination from every reachable vertex, continue until all reachable vertices have been visited.
    🔗
    🔗

    Subsection Shortest Paths from a Table

    A table can show the same connections and weights as a graph. A number gives the weight of a direct connection; a dash means there is no direct connection. A missing direct connection does not rule out a route through other vertices.
