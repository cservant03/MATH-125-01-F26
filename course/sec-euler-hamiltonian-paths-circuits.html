    Objectives: Learning Outcomes

    1. Distinguish routes that use every edge from routes that visit every vertex.

    Subsection Every edge or every vertex?

    A street sweeper must cover every street. A delivery driver must visit every delivery location. Both tasks involve a route, but the objects that must be covered are different.
    🔗

    Definition 158 Euler Path.

    🔗
    🔗

    Definition 159 Euler Circuit.

    🔗
    🔗

    Remark 160.

    An Euler route may revisit vertices. It must use each edge exactly once. Here, an open Euler path has different starting and ending vertices; an Euler circuit is a closed Euler path.
    🔗
    🔗
    For the connected graphs considered here, count the vertices of odd degree.
    🔗
    Odd-degree vertices What is possible?
    0 An Euler circuit exists. Start at any vertex.
    2 An Euler path exists. Start at one odd-degree vertex and end at the other.
    More than 2 Neither an Euler circuit nor an open Euler path exists.

    Remark 161.

    Check connectedness first. If edges lie in separate components, one route cannot cover them all.

    Subsection Finding an Euler route

    Algorithm 163 Fleury’s algorithm.

    1. Start at any vertex if finding an Euler circuit. If finding an Euler path, start at one of the two vertices with odd degree.
      🔗
      🔗
    2. Choose any edge leaving your current vertex, provided deleting that edge will not separate the graph into two disconnected sets of edges.
      🔗
      🔗
    3. Add that edge to your circuit, and delete it from the graph..
      🔗
      🔗
    4. Continue until every edge has been used exactly once.
      🔗
      🔗
    🔗

    Remark 166.

    Duplicating an edge means traveling an existing street again. It does not mean building a new street. For weighted graphs, minimize the added total weight, not just the number of duplicated edges. This is the closed-route Chinese Postman Problem.
    🔗
    🔗

    Subsection Finding a least-weight tour

    The Traveling Salesman Problem (TSP) asks for a Hamiltonian circuit with the smallest total edge weight. In the examples here, every pair of locations is connected and travel weights are the same in either direction.
    🔗

    Algorithm 171 Brute force (exhaustive search).

    1. List all possible Hamiltonian circuits
      🔗
      🔗
    2. Find the length of each circuit by adding the edge weights
      🔗
      🔗
    3. Select the circuit with minimal total weight
      🔗
      🔗

    Subsection Counting tours and using heuristics

    Algorithm 173 Nearest neighbor algorithm (NNA).

    1. Choose a starting vertex
      🔗
      🔗
    2. Move to the nearest unvisited vertex (the edge with smallest weight)
      🔗
      🔗
    3. Repeat until the circuit is complete
      🔗
      🔗
    🔗
    🔗

    Algorithm 174 Repeated nearest neighbor algorithm (RNNA).

    1. Do the Nearest Neighbor Algorithm starting at each vertex
      🔗
      🔗
    2. Choose the circuit produced with minimal total weight
      🔗
      🔗
    🔗
    🔗

    Remark 175.

    These quick methods can find useful tours, but neither guarantees the optimal tour.
    🔗
    🔗

    Subsection Choosing the cheapest eligible edges

    Algorithm 177 Sorted edges (cheapest link).

    1. Select the cheapest unused edge in the graph.
      🔗
      🔗
    2. Repeat step 1, adding the cheapest unused edge to the circuit, unless:
      🔗
      1. adding the edge would create a circuit that doesn’t contain all vertices, or
        🔗
        🔗
      2. adding the edge would give a vertex degree 3.
        🔗
        🔗
      🔗
    3. Repeat until a circuit containing all vertices is formed.
      🔗
      🔗
    🔗
    🔗

    Remark 178.

    Sorted edges does not guarantee a minimum-weight Hamiltonian circuit.
    🔗
    🔗
